Список эндпоинтов из технического задания. Столбец «Статус» заполняет тот, кто делает эндпоинт.

| Метод | Путь | Что делает | Кто | Статус |
|---|---|---|---|---|
| POST | /trips | создать поездку | Backend 1 |готово | 
| GET | /trips/<invite_code> | получить поездку по коду | Backend 1 | готово |
| POST | /trips/<id>/participants | добавить участника | Backend 1 | |
| GET | /trips/<id>/participants | список участников | Backend 1 | |
| GET | /trips/<id>/stops | список точек маршрута | Backend 3 | готово |
| POST | /trips/<id>/stops | добавить точку | Backend 3 | готово |
| PUT | /stops/<id> | изменить точку / статус | Backend 3 | |
| DELETE | /stops/<id> | удалить точку | Backend 3 | |
| GET | /trips/<id>/expenses | список расходов | Backend 2 | готово |
| POST | /trips/<id>/expenses | добавить расход | Backend 2 | готово |
| GET | /trips/<id>/balances | баланс и переводы | Backend 2 | готово |
| PUT | /trips/<id>/ticket | ссылка на билет, рейс, время | Backend 3 | |
| GET | /trips/<id>/checklist | чек-лист | Backend 2 | готово |
| POST | /trips/<id>/checklist | добавить пункт | Backend 2 | готово |
| PUT | /checklist/<id> | отметить выполненным | Backend 2 | готово |
| GET | /trips | список всех поездок (учебный пример, по ТЗ не нужен) | пример | |


## POST /trips: создание поездки

Создаёт поездку по названию (раздел 1.1 ТЗ). Участники добавляются отдельно через `POST /trips/<id>/participants`.

**Запрос**

```json
{"name": "Поездка в Казань"}
```

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `name` | string | да | Название поездки. Пробелы по краям обрезаются. Не пустое, не длиннее 100 символов |

**Ответ 201 Created**

```json
{
  "id": 1,
  "name": "Поездка в Казань",
  "invite_code": "avWrjn_nlxI",
  "ticket_link": null,
  "flight_number": null,
  "flight_time": null
}
```

`invite_code` генерируется сервером (`secrets.token_urlsafe(8)`) и уникален. По нему участники заходят по ссылке-приглашению.

**Ошибки: 400 Bad Request**

Тело ошибки всегда такое: `{"error": "текст на русском"}`.

| Когда | Текст ошибки |
|---|---|
| Тело запроса не JSON-объект (например, `[]` или не JSON вообще) | Тело запроса должно быть JSON-объектом |
| `name` отсутствует, пустой, из одних пробелов или не строка | Название поездки не может быть пустым |
| `name` длиннее 100 символов | Название поездки не должно быть длиннее 100 символов |
Ошибки всегда приходят в виде `{"error": "понятный текст на русском"}`.

## Точки маршрута

Точка маршрута:

| Поле | Тип | Что значит |
|---|---|---|
| `id` | число | номер точки |
| `trip_id` | число | поездка, к которой относится точка |
| `day_number` | число | номер дня поездки, от 1 |
| `title` | строка | название точки |
| `status` | строка | `proposed` (предложено) или `confirmed` (подтверждено) |

## GET /trips/<invite_code>: вход по ссылке

Возвращает поездку по коду приглашения. Участники заходят по ссылке вида `/trips/<invite_code>` без регистрации.

**Запрос**

Тела нет. Код приглашения передаётся в адресе: `GET /trips/avWrjn_nlxI`.

**Ответ 200 OK**

```json
{
"id": 1,
"name": "Поездка в Казань",
"invite_code": "avWrjn_nlxI",
"ticket_link": null,
"flight_number": null,
"flight_time": null
}
```

**Ошибка: 404 Not Found**

Если поездки с таким кодом нет:

```json
{"error": "Поездка с таким кодом не найдена"}
```

### GET /trips/<trip_id>/stops

Список точек поездки. Сортировка: по `day_number`, внутри одного дня по `id` (в порядке добавления).

Ответ `200`:

```json
[
  {"id": 2, "trip_id": 1, "day_number": 1, "title": "Старый город", "status": "confirmed"},
  {"id": 1, "trip_id": 1, "day_number": 2, "title": "Мцхета", "status": "proposed"}
]
```

Если у поездки нет точек, придёт пустой список `[]`.

| Код | Когда |
|---|---|
| 200 | всё хорошо |
| 404 | поездки нет: `{"error": "Поездка не найдена"}` |

### POST /trips/<trip_id>/stops

Добавить точку в поездку.

Тело запроса:

```json
{"day_number": 1, "title": "Старый город", "status": "confirmed"}
```

| Поле | Обязательно | Правило |
|---|---|---|
| `day_number` | да | целое число от 1 |
| `title` | да | непустая строка, пробелы по краям убираются |
| `status` | нет | `proposed` или `confirmed`, по умолчанию `proposed` |

Ответ `201`: созданная точка.

```json
{"id": 3, "trip_id": 1, "day_number": 1, "title": "Старый город", "status": "confirmed"}
```

| Код | Когда |
|---|---|
| 201 | точка создана |
| 400 | неверные данные, например `{"error": "Номер дня должен быть целым числом от 1"}` |
| 404 | поездки нет: `{"error": "Поездка не найдена"}` |

Сначала проверяется, есть ли поездка, потом данные: для несуществующей поездки ответ 404, даже если данные неверные.

## Расходы

### GET /trips/<id>/expenses

Список расходов поездки с долями участников, по порядку добавления. Для поездки без расходов: `[]`.

Ответ `200`:

```json
[
  {
    "id": 1,
    "trip_id": 1,
    "category": "еда",
    "payer_id": 1,
    "amount": 100.0,
    "shares": [
      {"participant_id": 1, "share_amount": 33.34},
      {"participant_id": 2, "share_amount": 33.33},
      {"participant_id": 3, "share_amount": 33.33}
    ]
  }
]
```

Ошибки: `404` — поездка не найдена.

### POST /trips/<id>/expenses

Добавляет расход и делит его поровну между выбранными участниками.

Запрос:

```json
{
  "amount": 100.00,
  "category": "еда",
  "payer_id": 1,
  "participant_ids": [1, 2, 3]
}
```

- `amount`: число больше нуля, округляется до двух знаков.
- `category`: одна из `еда`, `транспорт`, `жильё`, `развлечения`, `другое`.
- `payer_id`: участник этой поездки. Он может входить в `participant_ids` или нет.
- `participant_ids`: непустой список участников этой поездки без повторов.

Остаток копеек раздаётся по одной первым участникам списка, поэтому сумма долей всегда равна сумме расхода: 100 на троих = 33.34 + 33.33 + 33.33.

Ответ `201`: созданный расход в том же формате, что в списке.

Ошибки: `400` — неверные данные (`{"error": "Сумма должна быть больше нуля"}` и т. п.), `404` — поездка не найдена.

### GET /trips/<id>/balances

Баланс каждого участника и минимальный набор переводов, чтобы все рассчитались.

- Баланс = сумма расходов, которые участник оплатил (`payer_id`), минус сумма его долей (`share_amount`).
  Плюс: участнику должны. Минус: участник должен. Сумма всех балансов равна нулю.
- Переводы считаются жадно: самый большой должник платит самому большому кредитору меньшую из двух сумм, пока все балансы не станут нулевыми.
- Поездка без расходов: у всех баланс `0.0`, `transfers` пустой.

Ответ `200`:

```json
{
  "balances": [
    {"participant_id": 1, "name": "Иван Петров", "balance": -500.0},
    {"participant_id": 2, "name": "Мария Ким", "balance": 400.0},
    {"participant_id": 3, "name": "Пётр Лис", "balance": 100.0}
  ],
  "transfers": [
    {"from": "Иван Петров", "to": "Мария Ким", "amount": 400.0},
    {"from": "Иван Петров", "to": "Пётр Лис", "amount": 100.0}
  ]
}
```

Ошибки: `404` — поездка не найдена.

## Чек-лист

Пункт чек-листа:

| Поле | Тип | Что значит |
|---|---|---|
| `id` | число | номер пункта |
| `trip_id` | число | поездка, к которой относится пункт |
| `title` | строка | что нужно сделать |
| `is_checked` | true / false | выполнен ли пункт |

### GET /trips/<id>/checklist

Пункты поездки в порядке добавления. Если пунктов нет: `[]`.

Ответ `200`:

```json
[
  {"id": 1, "trip_id": 1, "title": "Взять паспорт", "is_checked": true},
  {"id": 2, "trip_id": 1, "title": "Купить страховку", "is_checked": false}
]
```

Ошибки: `404` — поездка не найдена.

### POST /trips/<id>/checklist

Добавить пункт. Новый пункт всегда без отметки.

Запрос:

```json
{"title": "Взять паспорт"}
```

- `title`: непустая строка, пробелы по краям убираются, не длиннее 100 символов.

Ответ `201`: созданный пункт.

```json
{"id": 1, "trip_id": 1, "title": "Взять паспорт", "is_checked": false}
```

Ошибки: `400` — пустое или неверное название, `404` — поездка не найдена.

### PUT /checklist/<id>

Поставить или снять отметку.

Запрос:

```json
{"is_checked": true}
```

- `is_checked`: только JSON `true` или `false`. Строка `"true"`, `1` или `null` дают ошибку 400.

Ответ `200`: обновлённый пункт.

Ошибки: `400` — неверное значение `is_checked`, `404` — пункт не найден. Сначала проверяется, есть ли пункт, потом данные.
