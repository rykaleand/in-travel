## POST /trips: создание поездки

Создаёт поездку по названию (раздел 1.1 ТЗ). Участники добавляются отдельно через `POST /trips/<id>/participants`.

**Запрос**

```json
{"name": "Поездка в Казань"}
```

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `name` | string | да | Название поездки. Пробелы по краям обрезаются. Не пустое, не длиннее 100 символов |

**Ответ 201 Created**

```json
{
  "id": 1,
  "name": "Поездка в Казань",
  "invite_code": "avWrjn_nlxI",
  "ticket_link": null,
  "flight_number": null,
  "flight_time": null
}
```

`invite_code` генерируется сервером (`secrets.token_urlsafe(8)`) и уникален. По нему участники заходят по ссылке-приглашению.

**Ошибки: 400 Bad Request**

Тело ошибки всегда такое: `{"error": "текст на русском"}`.

| Когда | Текст ошибки |
|---|---|
| Тело запроса не JSON-объект (например, `[]` или не JSON вообще) | Тело запроса должно быть JSON-объектом |
| `name` отсутствует, пустой, из одних пробелов или не строка | Название поездки не может быть пустым |
| `name` длиннее 100 символов | Название поездки не должно быть длиннее 100 символов |
Ошибки всегда приходят в виде `{"error": "понятный текст на русском"}`.

## Точки маршрута

Точка маршрута:

| Поле | Тип | Что значит |
|---|---|---|
| `id` | число | номер точки |
| `trip_id` | число | поездка, к которой относится точка |
| `day_number` | число | номер дня поездки, от 1 |
| `title` | строка | название точки |
| `status` | строка | `proposed` (предложено) или `confirmed` (подтверждено) |

### GET /trips/<trip_id>/stops

Список точек поездки. Сортировка: по `day_number`, внутри одного дня по `id` (в порядке добавления).

Ответ `200`:

```json
[
  {"id": 2, "trip_id": 1, "day_number": 1, "title": "Старый город", "status": "confirmed"},
  {"id": 1, "trip_id": 1, "day_number": 2, "title": "Мцхета", "status": "proposed"}
]
```

Если у поездки нет точек, придёт пустой список `[]`.

| Код | Когда |
|---|---|
| 200 | всё хорошо |
| 404 | поездки нет: `{"error": "Поездка не найдена"}` |

### POST /trips/<trip_id>/stops

Добавить точку в поездку.

Тело запроса:

```json
{"day_number": 1, "title": "Старый город", "status": "confirmed"}
```

| Поле | Обязательно | Правило |
|---|---|---|
| `day_number` | да | целое число от 1 |
| `title` | да | непустая строка, пробелы по краям убираются |
| `status` | нет | `proposed` или `confirmed`, по умолчанию `proposed` |

Ответ `201`: созданная точка.

```json
{"id": 3, "trip_id": 1, "day_number": 1, "title": "Старый город", "status": "confirmed"}
```

| Код | Когда |
|---|---|
| 201 | точка создана |
| 400 | неверные данные, например `{"error": "Номер дня должен быть целым числом от 1"}` |
| 404 | поездки нет: `{"error": "Поездка не найдена"}` |

Сначала проверяется, есть ли поездка, потом данные: для несуществующей поездки ответ 404, даже если данные неверные.

## Билет

Билет хранится полями поездки (`ticket_link`, `flight_number`, `flight_time`), отдельной таблицы нет.
Номер рейса и точное время участник вводит вручную (раздел 1.5 ТЗ).

### PUT /trips/<trip_id>/ticket

Сохранить билет поездки. Запрос заменяет билет целиком: поле, которого нет в запросе, станет `null`.
Поэтому форма должна отправлять все три поля, даже если меняется только одно.

Тело запроса:

```json
{
  "ticket_link": "https://www.aviasales.com/search/MOW0209TBS1",
  "flight_number": "SU 1234",
  "flight_time": "2026-09-02T14:30"
}
```

| Поле | Обязательно | Правило |
|---|---|---|
| `ticket_link` | нет | начинается с `http://` или `https://`. Ссылка Aviasales дополнительно разбирается (см. ниже) |
| `flight_number` | нет | строка |
| `flight_time` | нет | `ГГГГ-ММ-ДДTЧЧ:ММ` или `ГГГГ-ММ-ДДTЧЧ:ММ:СС`, без часового пояса. Так отправляет `<input type="datetime-local">` |

Пробелы по краям строк убираются. Пустая строка или `null` очищают поле.

Ответ `200`: сохранённый билет и разбор ссылки.

```json
{
  "trip_id": 1,
  "ticket_link": "https://www.aviasales.com/search/MOW0209TBS1",
  "flight_number": "SU 1234",
  "flight_time": "2026-09-02T14:30:00",
  "aviasales": {"origin": "MOW", "destination": "TBS", "day": 2, "month": 9}
}
```

`flight_time` всегда возвращается с секундами.

| Код | Когда |
|---|---|
| 200 | билет сохранён |
| 400 | неверные данные, например `{"error": "Ссылка на билет должна начинаться с http:// или https://"}` |
| 404 | поездки нет: `{"error": "Поездка не найдена"}` |

Тексты ошибок 400:

| Когда | Текст ошибки |
|---|---|
| Тело запроса не JSON-объект | Тело запроса должно быть JSON-объектом |
| Ссылка без `http://` / `https://` или без адреса сайта | Ссылка на билет должна начинаться с http:// или https:// |
| Ссылка Aviasales не того вида | Не удалось разобрать ссылку Aviasales: ожидается вид aviasales.com/search/MOW0209TBS1 |
| В ссылке Aviasales несуществующая дата (например, 31.02) | В ссылке Aviasales неверная дата |
| В ссылке Aviasales 0 пассажиров | В ссылке Aviasales должно быть не меньше одного пассажира |
| Неверный формат времени | Время рейса нужно указать в формате ГГГГ-ММ-ДДTЧЧ:ММ, например 2026-11-05T14:30 |
| Поле не строка | Ссылка на билет / Номер рейса / Время рейса должно быть строкой |

При ошибке ничего не сохраняется.

### Разбор ссылки Aviasales (поле `aviasales`)

Для frontend-задачи #34. Направление и дата берутся из самой ссылки (приложение Б ТЗ), в базе они отдельно не хранятся.

Ссылка считается ссылкой Aviasales, если сайт `aviasales.com` или `aviasales.ru` (с `www.` или без).
Ожидаемый вид: `https://www.aviasales.com/search/MOW0209TBS1`.

| Часть кода | Пример | Что значит |
|---|---|---|
| 3 заглавные буквы | `MOW` | код аэропорта (города) вылета |
| 2 цифры | `02` | день вылета |
| 2 цифры | `09` | месяц вылета |
| 3 заглавные буквы | `TBS` | код аэропорта (города) прилёта |
| 1–9 | `1` | число пассажиров (проверяется, но не возвращается) |

Значение поля `aviasales`:

| Ссылка | `aviasales` |
|---|---|
| Корректная ссылка Aviasales | `{"origin": "MOW", "destination": "TBS", "day": 2, "month": 9}` |
| Ссылка другого сайта | `null`, ссылка сохраняется без разбора |
| Ссылки нет | `null` |
| Некорректная ссылка Aviasales | билет не сохраняется, ответ 400 с текстом ошибки |

Поля объекта:

| Поле | Тип | Пример |
|---|---|---|
| `origin` | строка, 3 заглавные буквы | `"MOW"` |
| `destination` | строка, 3 заглавные буквы | `"TBS"` |
| `day` | число 1–31 | `2` |
| `month` | число 1–12 | `9` |

Года в ссылке нет, поэтому его нет и в ответе. Номера рейса и времени в ссылке тоже нет.
Ссылки туда и обратно (`.../search/MOW0209TBS15091`) не поддерживаются: в ТЗ описан только вид в одну сторону.

Пока поле `aviasales` есть только в ответе `PUT /trips/<id>/ticket`. В ответе поездки (`TripResponse`)
приходят `ticket_link`, `flight_number`, `flight_time`, но не `aviasales`.
