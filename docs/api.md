# API

Список эндпоинтов из технического задания. Столбец «Статус» заполняет тот, кто делает эндпоинт.

| Метод | Путь | Что делает | Кто | Статус |
|---|---|---|---|---|
| POST | /trips | создать поездку | Backend 1 | готово |
| GET | /trips/<invite_code> | получить поездку по коду | Backend 1 | готово |
| POST | /trips/<id>/participants | добавить участника | Backend 1 | готово |
| GET | /trips/<id>/participants | список участников | Backend 1 | готово |
| GET | /trips/<id>/stops | список точек маршрута | Backend 3 | готово |
| POST | /trips/<id>/stops | добавить точку | Backend 3 | готово |
| PUT | /stops/<id> | изменить точку / статус | Backend 3 | готово |
| DELETE | /stops/<id> | удалить точку | Backend 3 | готово |
| GET | /trips/<id>/expenses | список расходов | Backend 2 | готово |
| POST | /trips/<id>/expenses | добавить расход | Backend 2 | готово |
| GET | /trips/<id>/balances | баланс и переводы | Backend 2 | готово |
| PUT | /trips/<id>/ticket | ссылка на билет, рейс, время | Backend 3 | готово |
| GET | /trips/<id>/checklist | чек-лист | Backend 2 | готово |
| POST | /trips/<id>/checklist | добавить пункт | Backend 2 | готово |
| PUT | /checklist/<id> | отметить выполненным | Backend 2 | готово |
| GET | /trips | список всех поездок (учебный пример, по ТЗ не нужен) | пример | |


## POST /trips: создание поездки

Создаёт поездку по названию (раздел 1.1 ТЗ). Участники добавляются отдельно через `POST /trips/<id>/participants`.

**Запрос**

```json
{"name": "Поездка в Казань"}
```

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `name` | string | да | Название поездки. Пробелы по краям обрезаются. Не пустое, не длиннее 100 символов |

**Ответ 201 Created**

```json
{
  "id": 1,
  "name": "Поездка в Казань",
  "invite_code": "avWrjn_nlxI",
  "ticket_link": null,
  "flight_number": null,
  "flight_time": null,
  "aviasales": null
}
```

`invite_code` генерируется сервером (`secrets.token_urlsafe(8)`) и уникален. По нему участники заходят по ссылке-приглашению.

**Ошибки: 400 Bad Request**

Тело ошибки всегда такое: `{"error": "текст на русском"}`.

| Когда | Текст ошибки |
|---|---|
| Тело запроса не JSON-объект (например, `[]` или не JSON вообще) | Тело запроса должно быть JSON-объектом |
| `name` отсутствует, пустой, из одних пробелов или не строка | Название поездки не может быть пустым |
| `name` длиннее 100 символов | Название поездки не должно быть длиннее 100 символов |
Ошибки всегда приходят в виде `{"error": "понятный текст на русском"}`.

## Точки маршрута

Точка маршрута:

| Поле | Тип | Что значит |
|---|---|---|
| `id` | число | номер точки |
| `trip_id` | число | поездка, к которой относится точка |
| `day_number` | число | номер дня поездки, от 1 |
| `title` | строка | название точки |
| `status` | строка | `proposed` (предложено) или `confirmed` (подтверждено) |

## GET /trips/<invite_code>: вход по ссылке

Возвращает поездку по коду приглашения. Участники заходят по ссылке вида `/trips/<invite_code>` без регистрации.

**Запрос**

Тела нет. Код приглашения передаётся в адресе: `GET /trips/avWrjn_nlxI`.

**Ответ 200 OK**

```json
{
"id": 1,
"name": "Поездка в Казань",
"invite_code": "avWrjn_nlxI",
"ticket_link": null,
"flight_number": null,
"flight_time": null,
"aviasales": null
}
```

Если у поездки сохранена ссылка Aviasales, в `aviasales` придёт её разбор, например
`{"origin": "MOW", "destination": "TBS", "day": 2, "month": 9}` (см. раздел «Билет»).

**Ошибка: 404 Not Found**

Если поездки с таким кодом нет:

```json
{"error": "Поездка с таким кодом не найдена"}
```

## GET /trips/<id>/participants: список участников

Возвращает участников одной поездки. Если участников нет, возвращает пустой список.

**Запрос:** тела нет, `id` поездки в адресе: `GET /trips/1/participants`.

**Ответ 200 OK**

```json
[
  {"id": 1, "trip_id": 1, "first_name": "Анна", "last_name": "Иванова"}
]
```

**Ошибка: 404 Not Found**, если поездки нет: `{"error": "Поездка не найдена"}`.

## POST /trips/<id>/participants: добавить участника

Добавляет участника в поездку по имени и фамилии.

**Запрос**

```json
{"first_name": "Анна", "last_name": "Иванова"}
```

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `first_name` | string | да | Имя. Пробелы по краям обрезаются. Не пустое, не длиннее 50 символов. Дефисы и пробелы внутри допустимы |
| `last_name` | string | да | Фамилия, те же правила |

**Ответ 201 Created**

```json
{"id": 1, "trip_id": 1, "first_name": "Анна", "last_name": "Иванова"}
```

**Ошибки**

Тело ошибки всегда `{"error": "текст на русском"}`.

| Код | Когда | Текст ошибки |
|---|---|---|
| 404 | Поездки с таким `id` нет | Поездка не найдена |
| 400 | Тело запроса не JSON-объект | Тело запроса должно быть JSON-объектом |
| 400 | Имя отсутствует, пустое или из одних пробелов | Имя не может быть пустым |
| 400 | Фамилия отсутствует, пустая или из одних пробелов | Фамилия не может быть пустым |
| 400 | Имя или фамилия не строка | Имя должно быть строкой |
| 400 | Имя или фамилия длиннее 50 символов | Имя не должно быть длиннее 50 символов |

### GET /trips/<trip_id>/stops

Список точек поездки. Сортировка: по `day_number`, внутри одного дня по `id` (в порядке добавления).

Ответ `200`:

```json
[
  {"id": 2, "trip_id": 1, "day_number": 1, "title": "Старый город", "status": "confirmed", "latitude": 41.7151, "longitude": 44.8271},
  {"id": 1, "trip_id": 1, "day_number": 2, "title": "Мцхета", "status": "proposed", "latitude": null, "longitude": null}
]
```

Если у поездки нет точек, придёт пустой список `[]`.

| Код | Когда |
|---|---|
| 200 | всё хорошо |
| 404 | поездки нет: `{"error": "Поездка не найдена"}` |

### POST /trips/<trip_id>/stops

Добавить точку в поездку.

Тело запроса:

```json
{"day_number": 1, "title": "Старый город", "status": "confirmed", "latitude": 41.7151, "longitude": 44.8271}
```

| Поле | Обязательно | Правило |
|---|---|---|
| `day_number` | да | целое число от 1 |
| `title` | да | непустая строка, пробелы по краям убираются |
| `status` | нет | `proposed` или `confirmed`, по умолчанию `proposed` |
| `latitude`, `longitude` | нет | обе вместе: широта от -90 до 90, долгота от -180 до 180; конечные JSON-числа, не строки и не boolean. Обе `null` или обе пропущены — без координат |

Ответ `201`: созданная точка.

```json
{"id": 3, "trip_id": 1, "day_number": 1, "title": "Старый город", "status": "confirmed", "latitude": 41.7151, "longitude": 44.8271}
```

| Код | Когда |
|---|---|
| 201 | точка создана |
| 400 | неверные данные, например `{"error": "Номер дня должен быть целым числом от 1"}` |
| 404 | поездки нет: `{"error": "Поездка не найдена"}` |

Сначала проверяется, есть ли поездка, потом данные: для несуществующей поездки ответ 404, даже если данные неверные.

### PUT /stops/<stop_id>

Изменить точку: название, день, статус или координаты. Меняются только переданные поля, остальные остаются как были.
Для `title`, `day_number` и `status` значение `null` считается непереданным.
Для координат: обе пропущены — сохранить текущие; обе `null` — очистить; два числа — заменить. Одно поле или пара «число + null» дают 400. Ноль допустим.

Тело запроса (любые из полей, хотя бы одно):

```json
{"title": "Мцхета", "day_number": 2, "status": "confirmed", "latitude": 41.7151, "longitude": 44.8271}
```

Чтобы подтвердить точку или вернуть её в предложенные, достаточно передать только статус:

```json
{"status": "confirmed"}
```

| Поле | Обязательно | Правило |
|---|---|---|
| `title` | нет | непустая строка, пробелы по краям убираются |
| `day_number` | нет | целое число от 1 (строки, дроби и `true` не принимаются) |
| `status` | нет | `proposed` или `confirmed` |
| `latitude`, `longitude` | нет | только парой; те же диапазоны, что при создании; два `null` очищают координаты |

Ответ `200`: точка после изменения.

```json
{"id": 1, "trip_id": 1, "day_number": 2, "title": "Мцхета", "status": "confirmed", "latitude": 41.7151, "longitude": 44.8271}
```

| Код | Когда |
|---|---|
| 200 | точка изменена |
| 400 | неверные данные |
| 404 | точки нет: `{"error": "Точка маршрута не найдена"}` |

Тексты ошибок 400:

| Когда | Текст ошибки |
|---|---|
| Не передано ни одного изменяемого поля (в том числе null только у title/day_number/status) | Передайте хотя бы одно поле: title, day_number, status или пару latitude и longitude |
| `title` пустой, из одних пробелов или не строка | Укажите название точки |
| `day_number` не целое число от 1 | Номер дня должен быть целым числом от 1 |
| `status` не `proposed` и не `confirmed` | Статус точки может быть только proposed или confirmed |

Если хотя бы одно поле неверное, точка не меняется.
Сначала проверяется, есть ли точка: для несуществующей точки ответ 404, даже если данные неверные.

Координаты можно обновить отдельно: `{"latitude": 55.7539, "longitude": 37.6208}`.
Для удаления привязки к карте: `{"latitude": null, "longitude": null}`.

Ошибки координат (400): `Передайте latitude и longitude вместе`,
`latitude должна быть числом от -90 до 90`, `longitude должна быть числом от -180 до 180`.
При неверных координатах остальные поля также не сохраняются.
Старые клиенты могут продолжать отправлять запросы без координат; ответы теперь содержат оба поля (числа или `null`).

### DELETE /stops/<stop_id>

Удалить точку. Тела запроса нет.

Ответ `200`:

```json
{"success": true}
```

| Код | Когда |
|---|---|
| 200 | точка удалена |
| 404 | точки нет (или её уже удалили): `{"error": "Точка маршрута не найдена"}` |

## Билет

Билет хранится полями поездки (`ticket_link`, `flight_number`, `flight_time`), отдельной таблицы нет.
Номер рейса и точное время участник вводит вручную (раздел 1.5 ТЗ).

### PUT /trips/<trip_id>/ticket

Сохранить билет поездки. Запрос заменяет билет целиком: поле, которого нет в запросе, станет `null`.
Поэтому форма должна отправлять все три поля, даже если меняется только одно.

Тело запроса:

```json
{
  "ticket_link": "https://www.aviasales.com/search/MOW0209TBS1",
  "flight_number": "SU 1234",
  "flight_time": "2026-09-02T14:30"
}
```

| Поле | Обязательно | Правило |
|---|---|---|
| `ticket_link` | нет | начинается с `http://` или `https://`. Ссылка Aviasales дополнительно разбирается (см. ниже) |
| `flight_number` | нет | строка |
| `flight_time` | нет | `ГГГГ-ММ-ДДTЧЧ:ММ` или `ГГГГ-ММ-ДДTЧЧ:ММ:СС`, без часового пояса. Так отправляет `<input type="datetime-local">` |

Пробелы по краям строк убираются. Пустая строка или `null` очищают поле.

Ответ `200`: сохранённый билет и разбор ссылки.

```json
{
  "trip_id": 1,
  "ticket_link": "https://www.aviasales.com/search/MOW0209TBS1",
  "flight_number": "SU 1234",
  "flight_time": "2026-09-02T14:30:00",
  "aviasales": {"origin": "MOW", "destination": "TBS", "day": 2, "month": 9}
}
```

`flight_time` всегда возвращается с секундами.

| Код | Когда |
|---|---|
| 200 | билет сохранён |
| 400 | неверные данные, например `{"error": "Ссылка на билет должна начинаться с http:// или https://"}` |
| 404 | поездки нет: `{"error": "Поездка не найдена"}` |

Тексты ошибок 400:

| Когда | Текст ошибки |
|---|---|
| Тело запроса не JSON-объект | Тело запроса должно быть JSON-объектом |
| Ссылка без `http://` / `https://` или без адреса сайта | Ссылка на билет должна начинаться с http:// или https:// |
| Ссылка Aviasales не того вида | Не удалось разобрать ссылку Aviasales: ожидается вид aviasales.com/search/MOW0209TBS1 |
| В ссылке Aviasales несуществующая дата (например, 31.02) | В ссылке Aviasales неверная дата |
| В ссылке Aviasales 0 пассажиров | В ссылке Aviasales должно быть не меньше одного пассажира |
| Неверный формат времени | Время рейса нужно указать в формате ГГГГ-ММ-ДДTЧЧ:ММ, например 2026-11-05T14:30 |
| Поле не строка | Ссылка на билет / Номер рейса / Время рейса должно быть строкой |

При ошибке ничего не сохраняется.

### Разбор ссылки Aviasales (поле `aviasales`)

Для frontend-задачи #34. Направление и дата берутся из самой ссылки (приложение Б ТЗ), в базе они отдельно не хранятся.

Ссылка считается ссылкой Aviasales, если сайт `aviasales.com` или `aviasales.ru` (с `www.` или без).
Ожидаемый вид: `https://www.aviasales.com/search/MOW0209TBS1`.

| Часть кода | Пример | Что значит |
|---|---|---|
| 3 заглавные буквы | `MOW` | код аэропорта (города) вылета |
| 2 цифры | `02` | день вылета |
| 2 цифры | `09` | месяц вылета |
| 3 заглавные буквы | `TBS` | код аэропорта (города) прилёта |
| 1–9 | `1` | число пассажиров (проверяется, но не возвращается) |

Значение поля `aviasales`:

| Ссылка | `aviasales` |
|---|---|
| Корректная ссылка Aviasales | `{"origin": "MOW", "destination": "TBS", "day": 2, "month": 9}` |
| Ссылка другого сайта | `null`, ссылка сохраняется без разбора |
| Ссылки нет | `null` |
| Некорректная ссылка Aviasales | билет не сохраняется, ответ 400 с текстом ошибки |

Поля объекта:

| Поле | Тип | Пример |
|---|---|---|
| `origin` | строка, 3 заглавные буквы | `"MOW"` |
| `destination` | строка, 3 заглавные буквы | `"TBS"` |
| `day` | число 1–31 | `2` |
| `month` | число 1–12 | `9` |

Года в ссылке нет, поэтому его нет и в ответе. Номера рейса и времени в ссылке тоже нет.
Ссылки туда и обратно (`.../search/MOW0209TBS15091`) не поддерживаются: в ТЗ описан только вид в одну сторону.

Поле `aviasales` приходит во всех ответах с поездкой (`GET /trips/<invite_code>`, `POST /trips`, `GET /trips`)
и в ответе `PUT /trips/<id>/ticket`. Поэтому после обновления страницы фронт снова получит направление и дату.
В базе разбор не хранится: сервер каждый раз разбирает сохранённую `ticket_link`. Запросов к Aviasales нет,
разбирается только текст ссылки.

## Расходы

### GET /trips/<id>/expenses

Список расходов поездки с долями участников, по порядку добавления. Для поездки без расходов: `[]`.

Ответ `200`:

```json
[
  {
    "id": 1,
    "trip_id": 1,
    "category": "еда",
    "payer_id": 1,
    "amount": 100.0,
    "shares": [
      {"participant_id": 1, "share_amount": 33.34},
      {"participant_id": 2, "share_amount": 33.33},
      {"participant_id": 3, "share_amount": 33.33}
    ]
  }
]
```

Ошибки: `404` — поездка не найдена.

### POST /trips/<id>/expenses

Добавляет расход и делит его поровну между выбранными участниками.

Запрос:

```json
{
  "amount": 100.00,
  "category": "еда",
  "payer_id": 1,
  "participant_ids": [1, 2, 3]
}
```

- `amount`: число больше нуля, округляется до двух знаков.
- `category`: одна из `еда`, `транспорт`, `жильё`, `развлечения`, `другое`.
- `payer_id`: участник этой поездки. Он может входить в `participant_ids` или нет.
- `participant_ids`: непустой список участников этой поездки без повторов.

Остаток копеек раздаётся по одной первым участникам списка, поэтому сумма долей всегда равна сумме расхода: 100 на троих = 33.34 + 33.33 + 33.33.

Ответ `201`: созданный расход в том же формате, что в списке.

Ошибки: `400` — неверные данные (`{"error": "Сумма должна быть больше нуля"}` и т. п.), `404` — поездка не найдена.

### GET /trips/<id>/balances

Баланс каждого участника и минимальный набор переводов, чтобы все рассчитались.

- Баланс = сумма расходов, которые участник оплатил (`payer_id`), минус сумма его долей (`share_amount`).
  Плюс: участнику должны. Минус: участник должен. Сумма всех балансов равна нулю.
- Переводы считаются жадно: самый большой должник платит самому большому кредитору меньшую из двух сумм, пока все балансы не станут нулевыми.
- Поездка без расходов: у всех баланс `0.0`, `transfers` пустой.

Ответ `200`:

```json
{
  "balances": [
    {"participant_id": 1, "name": "Иван Петров", "balance": -500.0},
    {"participant_id": 2, "name": "Мария Ким", "balance": 400.0},
    {"participant_id": 3, "name": "Пётр Лис", "balance": 100.0}
  ],
  "transfers": [
    {"from": "Иван Петров", "to": "Мария Ким", "amount": 400.0},
    {"from": "Иван Петров", "to": "Пётр Лис", "amount": 100.0}
  ]
}
```

Ошибки: `404` — поездка не найдена.

## Чек-лист

Пункт чек-листа:

| Поле | Тип | Что значит |
|---|---|---|
| `id` | число | номер пункта |
| `trip_id` | число | поездка, к которой относится пункт |
| `title` | строка | что нужно сделать |
| `is_checked` | true / false | выполнен ли пункт |

### GET /trips/<id>/checklist

Пункты поездки в порядке добавления. Если пунктов нет: `[]`.

Ответ `200`:

```json
[
```

### POST /trips/<id>/checklist

Добавить пункт. Новый пункт всегда без отметки.

Запрос:

```json
{"title": "Взять паспорт"}
```

- `title`: непустая строка, пробелы по краям убираются, не длиннее 100 символов.

Ответ `201`: созданный пункт.

```json
{"id": 1, "trip_id": 1, "title": "Взять паспорт", "is_checked": false}
```

Ошибки: `400` — пустое или неверное название, `404` — поездка не найдена.

### PUT /checklist/<id>

Поставить или снять отметку.

Запрос:

```json
{"is_checked": true}
```

- `is_checked`: только JSON `true` или `false`. Строка `"true"`, `1` или `null` дают ошибку 400.

Ответ `200`: обновлённый пункт.

Ошибки: `400` — неверное значение `is_checked`, `404` — пункт не найден. Сначала проверяется, есть ли пункт, потом данные.
