# CLAUDE.md

Инструкция для Claude Code в этом репозитории.

## О проекте

**ВПуть (in-travel)**: веб-сервис для совместного планирования поездок компанией.
Участники заходят по ссылке-приглашению без регистрации, вместе собирают маршрут,
ведут общий бюджет (сервис считает, кто кому должен) и хранят информацию о билетах.

Это учебный проект, его делают студенты-первокурсники. Срок: с 12.10.2026 по 30.11.2026.
Полное ТЗ: `docs/technical-specification.docx`. Список эндпоинтов: `docs/api.md`.

## Как помогать

- Пользователи начинающие. Объясняй простыми словами, что делает код и зачем.
- Выбирай самое простое решение. Не добавляй библиотеки, паттерны и инфраструктуру,
  которых нет в стеке, без согласования с руководителем проекта.
- Делай небольшие изменения, по одной задаче за раз. Работай в файлах той роли,
  за которую отвечает пользователь (таблица в `README.md`). Если нужно изменить чужой файл,
  скажи об этом.
- Перед правкой прочитай соседние файлы и держись их стиля.
- Предлагай шаги, которые студент сможет понять и повторить, а не огромные куски кода без объяснений.
- Комментарии в коде пиши на русском, имена переменных и функций на английском.

## Стек (менять нельзя без согласования)

- Backend: Python, Flask, Flask-SQLAlchemy, SQLite, flask-cors
- Frontend: React (Vite), JavaScript, запросы через `fetch`
- Без Docker, PostgreSQL, Redux и TypeScript

## Структура

- `backend/app/models/`: таблицы базы данных
- `backend/app/routes/`: эндпоинты API, один файл на раздел
- `backend/app/services/`: бизнес-логика без Flask (расчёт долгов, разбор ссылок)
- `backend/tests/`: автотесты (pytest)
- `frontend/src/api/`: запросы к бэкенду
- `frontend/src/pages/`, `frontend/src/components/`: экраны и их части
- `docs/`: ТЗ, список эндпоинтов, макеты

## Данные

Шесть таблиц: TRIPS, PARTICIPANTS, ROUTE_STOPS, EXPENSES, EXPENSE_SHARES, CHECKLIST_ITEMS.
Все, кроме TRIPS, ссылаются на `trip_id`. Пользователей нет: участник это имя и фамилия внутри поездки.
Информация о билете хранится полями в TRIPS (`ticket_link`, `flight_number`, `flight_time`).

## Правила backend

- Пути и методы эндпоинтов строго по `docs/api.md` и ТЗ. Добавил или изменил эндпоинт: обнови `docs/api.md`.
- Ответы в JSON. Ошибки в формате `{"error": "понятный текст на русском"}` с кодом 400 или 404.
- Проверяй входные данные: непустые строки, сумма больше нуля, статус точки только `proposed` или `confirmed`,
  категория расхода из `constants.py`.
- Сумма долей расхода равна сумме расхода, деньги округляются до двух знаков.
- На каждый эндпоинт и на расчёт долгов пиши тест.
- Логику расчётов держи в `services/`, а не в обработчиках маршрутов.

## Правила frontend

- Функциональные компоненты и хуки (`useState`, `useEffect`). Менеджеры состояния не нужны.
- Все запросы к серверу только через `src/api/client.js`.
- Тексты интерфейса на русском. Цвета и шрифты берём из `src/styles/` по макетам дизайнера.
- Для каждого экрана продумай три состояния: загрузка, пустой список, ошибка.
- Вёрстка должна работать на экранах от 360 пикселей шириной.

## Не входит в MVP (не предлагай и не добавляй)

Авторизация, голосование за точки маршрута в реальном времени, live-статус рейсов,
свои категории расходов.

## Команды

```bash
# backend
cd backend && source .venv/bin/activate && python run.py   # http://localhost:5000
cd backend && pytest                                       # тесты

# frontend
cd frontend && npm run dev                                 # http://localhost:5173
```
